# 小屋系统 v4 素材规范

## 核心决策

v4 是后续小屋素材的正式生产区。正式可见素材必须通过 Codex 的 `image_gen` 出图工具生成，不使用代码、HTML/CSS、SVG 或手工绘制来替代背景、家具、人物动作等视觉资产。

允许的本地后处理仅限于：

- 透明背景抠图、裁切、切帧、压缩。
- 按固定画布摆放生成预览图。
- 复制到程序资源目录并校验尺寸、透明度和锚点。

不允许的做法：

- 用代码手搓可见家具、墙面、角色动作或装饰。
- 让人物动作自带已经存在于家具层的大件物品。
- 只生成整张小屋图，然后把互动点硬贴上去。

## 画布

- 逻辑画布：`1792 x 1024`。
- 视角：固定像素风斜俯视室内视角。
- 比例：所有背景、家具、人物动作都必须匹配同一画布比例。
- 网格：以 32px 为主网格，允许 8px 微调。
- 渲染：像素风但边缘干净，不要使用模糊、真实照片质感或厚重阴影。

## 目录结构

```text
v4/
├── asset-spec.md          # 本文件
├── anchors.json           # 家具和人物动作锚点
├── background/            # 空房间底图
├── objects/               # 独立家具透明 PNG
├── characters/            # 人物锚点动作透明 PNG
├── raw/                   # image_gen 原始输出、绿幕图、合集图
└── preview/               # 组合预览、遮挡检查、锚点检查
```

## 分层规则

1. `background/empty-room.png` 只包含房间结构：墙、地板、窗、门、分区、基础通道。
2. `objects/*.png` 只包含家具主体、设备主体和家具自带的小物件，例如桌上茶具、侧向电脑/游戏机、床品。
3. `characters/*.png` 只包含人物和人物手持的小物件，例如杯子、书、笔。
4. 家具已经包含桌子、电脑、显示器、沙发、床、椅子时，人物动作不得重复携带这些大件。
5. 人物必须按家具朝向生成动作，不能出现背向家具、朝错方向、坐点偏离或遮挡关键家具面的问题。

## 互动槽位模型

后续家具优先设计为“主体物件 + 空互动位”，不要默认画成完整使用状态。

- 电脑/游戏：家具层只画侧向大屏幕、游戏主机或桌面设备，旁边保留一个明确空位；默认采用手柄互动，不需要键盘。人物到位后，用人物动作层补上坐下、拿手柄等动作。
- 茶几：家具层只画茶几和茶具，前侧或左下保留坐姿空位；人物动作层坐下拿杯子，面向茶几。
- 书桌：家具层只画桌子、书本、台灯等主体，前侧保留坐姿空位；如果坐姿高度不够，人物动作层可以自带一把小椅子。按当前小屋透视，人物应为三分之二背面，身体和椅子略朝左上方，面向桌面。允许人物/椅子遮住桌子前缘，前提是透视和接触关系正确。
- 沙发/客厅：家具层可画沙发和茶几，但人物坐位要留清楚；人物动作层坐到预留位读书或休息。
- 床：床可以作为完整家具，睡觉动作直接生成匹配床面透视的睡姿，叠在床上，不需要额外复杂图层。

这种模型的优先级高于“家具完整展示”。如果完整家具会导致角色动作和家具重复、叠椅子、朝向冲突，就必须改成互动槽位版本。

## 出图提示词硬约束

每次生成背景、家具或人物动作时，提示词必须包含：

- 固定画布和视角：`1792x1024 isometric pixel-art room canvas`。
- 同一角色设定：严格参考用户提供的爱弥斯原图，保留高侧马尾粉发、额前卷翘刘海、星形金色眼睛、白蓝渐变花瓣裙、蓝色蝴蝶结和白色小翅膀等关键特征。
- 同一光源：柔和室内光，不能每个家具有不同方向的阴影。
- 透明或可抠图要求：家具和人物动作生成在纯色绿幕背景或透明需求流程中，后处理为透明 PNG。
- 锚点要求：说明家具位置、人物站/坐点、朝向、避免遮挡的区域。
- 禁止项：不要额外生成未要求的大件家具、游戏机、屏幕、桌子、沙发、床、椅子。

## 特殊互动规则

- 电脑/游戏位建议改成侧向展示：设备主体在左侧或后侧，右侧/前侧留空互动位。屏幕要足够大，默认不画键盘。`play_game_anchor` 人物动作进入空位后坐下并手持小手柄，但不得自带椅子、桌子、电脑、显示器或游戏机。
- 如果电竞桌已经包含椅子，`play_game_anchor` 人物动作必须表现为坐在已有椅子上，不得再生成椅子。更推荐家具层不画椅子，只留空位让人物动作完整占位。
- 茶几动作必须面向茶几方向，人物不能朝反方向喝茶；如果茶几在右侧，人物应位于茶几左下/前侧并朝向右上或右侧。
- 书桌动作必须三分之二背对用户、略朝左上并面向书桌；不得额外生成一张书桌。若家具层没有椅子，动作层允许自带匹配透视的小椅子。
- 任何动作需要坐姿时，优先采用“家具留空位 + 人物动作补坐姿”的方式。只有对应家具没有座位且不会产生叠加冲突时，才允许人物自带小坐垫或小椅子。

## 生成顺序

1. 先生成 `background/empty-room.png`。
2. 再生成家具：每个家具单独出图，并记录到 `anchors.json`。
3. 再生成人物动作：每个动作绑定一个家具锚点，不单独发散创作。
4. 最后生成 `preview/*.png` 做叠放检查。

任何新增家具进入正式目录前，必须同步补充：

- 家具文件。
- `anchors.json` 中的家具坐标。
- 至少一个匹配该家具的人物动作或明确标记 `interaction_status: "pending_pose"`。
- 一张预览检查图。

## 验收标准

- 背景、家具、人物动作在同一视角和比例下自然对齐。
- 人物动作与家具语义一致：喝茶面对茶几，玩游戏面对已有电脑桌，读写面对书桌。
- 人物不穿模、不遮挡关键家具功能面。
- 家具不漂浮、不贴错透视、不产生与背景不一致的投影。
- 所有正式家具和人物动作必须是透明 PNG。
- 预览图必须能说明锚点关系，不只展示单个素材。
